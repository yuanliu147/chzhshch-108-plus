# chan-viewer 设计说明

缠论可视化学习工具。目的：①掌握 原始K线→包含处理→分型→笔→线段→中枢→走势类型→背驰→买卖点 的完整转换链；②分型标记练习；③理解"千人千缠"——同一份数据、不同口径画出不同结构，口径分歧显式化、可对比、可溯源；④多周期区间套——日线/30分/5分 联立，大级别背驰段逐级下钻次级别转折点。

- 形态：本地小服务（React + Node + TS）。覆盖手册第 1–8 关 + 多周期区间套。
- 数据主源：baostock 日线 SQLite（`baostock.db`）+ 分钟 SQLite（`baostock_min.db`，仅 5m/不复权/部分股票），node 内置 `node:sqlite` 只读访问，零第三方数据库依赖。
- 规格唯一来源：`../缠论108课_研究整理/新手手册/手册正文.html`；参考内核 `配图自检.py`（第 1–8 关断言）。
- 本文件的「引擎操作规格」是 TS 引擎与 Python 参考管线共同遵守的判定细则，交叉核验要求两者逐根事件 0 diff。

## 架构

```
chan-viewer/
├ packages/engine/   # 纯 TS 零依赖引擎，单一事实源（web 与交叉核验 CLI 共用）
├ apps/server/       # node:http + node:sqlite，零运行时依赖，只读供数
├ apps/web/          # React + Vite + zustand + ECharts + antd（控制层），四模式：学习/对比/练习/多周期
├ tools/             # reference_pipeline.py cross_check.py page_check.js dev.js
└ 报告/              # 交叉核验.json 页面核验.json 截图
```

依赖方向：web→engine（Vite 直编 TS 源码）；server 不依赖 engine（哑管道）。口径切换/回放/对比全部在 web 端用共享引擎即时重算。

## 引擎操作规格（判定细则）

### 输入与精度
- 输入：已走完的原始K线序列，只用 high/low（62课「这里不分阳线阴线，只看K线高低点」）。停牌占位行由 server 过滤（trade_status=1），引擎不处理停牌。
- 精度口径 `precision.digits`：处理前对 high/low 做四舍五入（half-up，`Math.round(v*10^d)/10^d`）；`'raw'` 不舍入。依据：59课个位vs两位小数改变划分、81课0.08价差案例。

### 第1关 包含处理（62、65课）
- 包含定义：`contains(a,b) = b.low>=a.low && b.high<=a.high`；`either = contains(a,b)||contains(b,a)`。区间表示 `[low, high]`。
- 顺序处理：新原始K线只与**尾根有效K线**比较；无包含则追加为新有效K线；有包含则按方向合并改写尾根。不传递、禁止全局取极值（65课「包含关系，不符合传递律」）。
- 合并：向上 `(max(low), max(high))`；向下 `(min(low), min(high))`（62课原文）。
- 方向判定（`mergeDir='回找非包含'`，原文口径）：尾根为第n根，往前找与尾根不构成包含的最近一根有效K线（第n-1根）。`gn>=gn-1`→向上；`dn<=dn-1`→向下；两者不可能同时成立（65课）；都不成立则继续往前找。有效K线序列两两无包含，故通常即前一根。
- 起点方向：最左端无第n-1根时，用 `config.startDir`（事先约定），并发「起点方向」事件写日志（65课）。
- 对照口径 `mergeDir='直接用前一根'`（**错误示范**）：用被合并两根自身判方向（`new.high>=tail.high`→向上，否则向下）。包含时方向无定义，此口径会抹掉新极值并可能重新引入包含（手册 fig-fangxiang 警示案例）。

### 第2关 分型（62、77课）
- 输入必须是有效K线。顶分型：中间根高点与低点都**严格**是三根中最高（`top3`）；底分型相反（`bot3`）。
- 候选/确认的机械定义（遮右重放不回填的落点）：
  - 三根结构 (V[L-3], V[L-2], V[L-1]) 的中间根 V[L-2] 构成分型时，若第三根 V[L-1] 仍是尾根 → **候选**（第三根已走完=可知，但仍可能被后续合并改写）。
  - 当新有效K线**追加**（尾根前进），原候选的第三根冻结 → **确认**，永不撤销。
  - 合并改写尾根时重估候选：不成立→发「分型撤销」+原因；类型改变→先撤销再发新候选。
  - 任一时刻至多一个候选分型（最右三根结构）。
- 结合律（77课）：分型层标出所有三根结构；相邻分型共用K线的问题**交给第3关成笔规则处理**（手册第2关判定步骤4原文）。

### 第3关 笔（77课三步骤的操作化）
- 成笔条件（端点为已确认分型 e→f，一顶一底）：
  - 独立K线：`f.middle - e.middle >= 4`（顶底之间至少1根不属于两分型的K线； middle 差4 ⇔ 顶分型首根到底分型尾根共5根）。
  - 价格区间条件：顶分型中间根区间 `[tLow,tHigh]` 至少有一部分高于底分型中间根区间 `[bLow,bHigh]` ⇔ `tHigh > bHigh`（区间条件，不是比顶底两个价；手册 fig-bi-jiage）。
- 增量算法（维护保留分型序列 K 与笔列表）：
  1. 新确认分型 f 到达。K 空 → f 为候选起点。
  2. f 与 K 尾根 e 同类：
     - f 严格更极端（顶更高/底更低）→ **级联单向剔除**：不断弹出 K 尾同类且不如 f 极端的分型（发「剔除」，原因「前顶低于后顶/前底高于后底」）；若被弹出的 e 是最后一笔的终点 → 发「改端点」；f 入 K。相等或前面更极端 → f 直接入 K（先保留，成同类串）。
  3. f 与 K 尾根 e 异类：
     - 先解析 K 尾同类串：取串中**最先一个**（必为最极端），其余全部「剔除」（原因「同串取首」）。
     - 检查 e→f 成笔条件。满足：若存在以 e 终点的笔 → 该笔「笔确认」；新建候选笔 e→f（「笔候选」）；f 入 K。
     - 不满足：f 被「剔除」（原因「独立K线不足」或「价格区间条件不满足」），K 不变。
  4. 笔确认时机：**下一笔形成时，上一笔才确认**；最后一笔恒为候选。否则更极端的同类分型会破坏已确认笔（违反遮右不回填）。
- 对照口径（均标注**社区/非原文**，手册坑清单「用社区流传的『固定几根K线』当成笔标准（本地原文没有这个口径）」）：
  - `社区老笔`：独立K线条件同77课；价格条件放宽为**比两个价** `tHigh > bLow`（顶高于底即可）。
  - `社区新笔`：独立K线放宽为 `middle差>=3`（允许顶底分型共用1根K线，4根成笔）；价格条件同77课区间条件。

### 第4关 线段（65/67/78课，特征序列分型法）
- 线段≥3笔且前三笔有重叠；向上线段由 S1X1S2X2… 构成，特征序列=反向笔（向下笔）。把特征元素视作K线做非包含处理（标准化，口径 `segMerge`）后找顶/底分型。
- 结束两情况：第一种（分型一二元素无缺口）→ 线段止于分型极值；第二种（有缺口）→ 挂起，等第二特征序列出反向分型才确认；挂起中若同向创新高/低则破坏不成立、撤销挂起（78课）。
- 实现采用**纯函数 `detectSegments(已确认笔)` 重算**：已确认笔不可变且只增 ⇒ 划分对前缀单调，天然满足遮右不回填；末尾留候选。
- 标准差的起始方向种子、候选淘汰顺序等原文未明示 → 标为**实现假设**。

### 第5关 中枢（17/18/20/33课）
- 连续三个次级别构件（`centerUnit`=线段中枢/笔中枢）重叠构成中枢。核心区间=前三构件共同重叠 `[ZD,ZG]`（20课简化式）；外围 GG/DD/G/D 按 20课在同向 Z 段上计算（`centerBounds`）。
- 延伸=后续构件重叠核心则延续（更新外围、segCount++）；破坏=离开+回抽不回（连续两个不重叠构件）→ 确认终结；9段升级（`centerUpgrade`，初始3段+延伸达9段即升级为更大级别）。
- 纯函数 `detectCenters(已确认构件)` 重算，末尾留候选。

### 第6关 走势类型（17/18/20课）
- 由已确认中枢推导：盘整=单中枢；趋势=≥2个同向且依次不重叠的中枢（上涨/下跌）。不重叠口径 `trendOverlap`=核心不重叠（ZG/ZD）/外围也不重叠（GG/DD，20课更严）。
- 纯函数 `detectTrends` 把中枢分成运行段，运行段被新中枢关闭即确认，末段候选。

### 第7关 背驰（24/25/27/33课）
- 以中枢为锚比较进入段(b)与离开段(c)力度，c<b 则背驰。趋势背驰=趋势运行段末中枢；盘整背驰=盘整运行段中枢。
- 窗口（稳健、非退化，实现假设的简化）：b段=[前一同级中枢.startRaw, 末中枢.startRaw]；c段=[末中枢.startRaw, 走势终结极值所在根]。
- 力度口径 `divMetric`：MACD面积（段内同向柱面积和，需 close）/ 中枢视角几何（段净位移 |末价-初价|，纯 high/low）。候选（末段进行中）MACD 用 ×2 估算整段（24课），标 est。
- MACD(12,26,9)：`macd.ts` 零依赖，EMA k=2/(n+1)、种子=首根 close（实现假设）；dif=ema12-ema26、dea=ema(dif,9)、hist=2*(dif-dea)；PIT 因果。

### 第8关 买卖点（20/21/101课）
- 一买/一卖=下跌趋势/上涨趋势的趋势背驰转折点；三买/三卖=离开中枢后**首次**回试分型不破边界（三买=向上离开后首个底分型低点不破 ZG；三卖镜像）；二买/二卖=一买/一卖后回抽再探底的分型。
- 口径：`bsp3Touch` 不跌破ZG(20课>=)/不触及ZG(21课>)；`bsp2Filter` 允许二买低于一买(101课原文)/过滤二买须高于一买（**实现假设**研究过滤器）。
- 买卖点存 atRaw（结构位置）与 confirmedAt（首次可知）——事后性由 compute(prefix) 免费获得。id 按内在 key 持久化（首次出现赋值），保证前缀一致。

### 事件模型
```
Event = { at: 原始K线下标, kind, reason: 中文原因, cite: 课号数组, refs: 涉及的原始K线下标, id?: 对象id }
kind ∈ 起点方向 | 合并 | 分型候选 | 分型确认 | 分型撤销 | 笔候选 | 笔确认 | 改端点 | 剔除
       | 线段确认 | 中枢确认 | 走势类型 | 背驰确认 | 买点确认 | 卖点确认
```
- 每根原始K线到达：先包含处理（合并事件含方向来源 refs），再分型层（候选/确认/撤销），再笔层（候选/确认/改端点/剔除）。
- 所有对象带 refs（原始K线下标区间），合并K线可溯源到源K线。
- `configId` = 配置规范化 JSON 的 FNV-1a 哈希，贯穿结果/练习记录/对比会话。

### 可测试性质（vitest 门禁）
- P1 前缀一致：∀n，compute(前n根).已确认集合 == 全量事件流截断至 n 折叠出的已确认集合。
- P2 批==增量拼接；P3 已确认对象不出现在任何后续撤销/改端点事件。
- P4 输出有效K线两两无包含（62课收尾自检；错误示范口径除外）。
- P5 笔顶底交替。
- P6 线段方向交替、首尾相接、已确认对前缀稳定。
- P7 中枢核心有效(ZD<=ZG)、外围包络(GG>=ZG/DD<=ZD)、已确认对前缀稳定。
- P8 走势类型盘整单中枢、趋势同向不重叠、已确认对前缀稳定。
- P9 背驰 c<b、已确认对前缀稳定。

## 服务端接口（node:http + node:sqlite，零运行时依赖）
- `GET /api/symbols?q&kind&includeDelisted`：stock_basic(type=1)+指数，退市/指数标记，limit 50。
- `GET /api/kline?code&adjust&start&end|limit`：adjust 必填（1后/2前/3不复权），limit 缺省400上限2000；强制 code+adjustflag 谓词走 PK 索引；过滤 trade_status=1；指数忽略 adjust 并标注。返回 bars+meta{source, adjust, filteredSuspended, dataAsOf, 逐根is_st, codeName, 复权基准日, warning}。前复权随最新分红改写历史→提示 PIT 审计建议后复权。
- `GET /api/mincap?code`：探测分钟线可用性（hasMin/count/firstTime/lastTime）。
- `GET /api/minkline?code&freq&start&end&limit`：分钟线（仅股票、仅不复权 adjustflag=3），freq=5/15/30/60（15/30/60 由 5m 按交易时段聚合：09:30–11:30、13:00–15:00，不跨午休/跨日，OHLC=首开/最高/最低/末收、量额求和，time=桶结束时间）；指数→400；无分钟线标的→hasMin=false+warning。date 字段承载完整时间戳。
- 分钟库为独立 `baostock_min.db`（`getMinDb()` 只读连接，busy_timeout）。
- node:sqlite 在 node 22 带 ExperimentalWarning，启动脚本过滤。
- 生产模式 server 兼静态托管 web dist；开发 Vite proxy。`tools/dev.js` 一条命令起全套。

## 前端四模式（zustand 单 store）
- 学习：标的/复权/口径选择器（12 维，每维 tooltip 引文+来源徽标）；图层开关（合并K线/分型/笔/线段/中枢/背驰/买卖点/候选）；回放游标=事件流按 at<=cursor 截断折叠（P1 保证合法）；事件日志点选→图上高亮 refs；侧栏走势类型摘要。
- 对比（千人千缠）：同数据双配置并排，按原始K线下标对齐 diff，差异清单带引文；预设对覆盖各口径分歧（77课vs社区老笔、精度、起点方向、回找vs直接用、特征序列做/不做包含、端点相接、笔中枢vs线段中枢、背驰MACDvs几何、三买边界、二买过滤）。
- 练习：种子化选窗（记录 code/区间/configId/dataAsOf）→遮右→点选顶/底→对照引擎确认分型→逐标记判定+事件解释→计分；localStorage 审计记录。（线段/中枢区间标记练习为后续增强。）
- 多周期区间套：初始日线主图；按当前结构/视窗进入30分钟，再进入5分钟，当前层是主图，上级缩为紧凑上下文。三层目标共享同一物理截止，父级结构/视窗通过真实交易覆盖映射，不复制不同周期下标；无覆盖阻断而不是跳最新数据。日线独立可用，分钟缺失只限制下钻。
- 渲染：ECharts candlestick + custom series（合并K线宽柱、中枢核心带+外围矩形、分型箭头、笔/线段折线+候选虚线、背驰菱形、买卖点 pin）+ 右侧价格轴、VOL/MACD可拖动副图、固定数据窗与两点测距；价格/时间/成交量/成交额单位显式，价格轴按可见区缩放；分钟线日内时间轴（MM-DD HH:MM、日界分隔），横向等距代表一根K线而非自然时间。
- 控制层：标准控件交给 antd，ConfigProvider 暗色算法+主题令牌沿用终端调色板（theme.ts）；图表、事件日志、图例色块、布局与滚动条保留自定义视觉。合并展示「实体：原始/合并」与回放速度为常驻即时控件。
